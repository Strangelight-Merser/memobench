# MemoBench v2 作品介绍（10 页内容稿）

> **开发候选，尚非最终排版 PDF。** 定位：面向 openKylin 智能体的证据驱动记忆回归评测工具。数据 `pending_review`；真实智能体与 openKylin 未验证；LLM 结果待补。本文按 E1 组织为 10 页，所有待实测项必须补原始证据后才能改为完成。规则与赛程依据仓库 `plan-v2/FULL_RESPONSE.md`，本轮未联网复核。

## 第1页｜项目摘要与问题

“项目周报目录已经改了，智能体却继续写入旧路径。”这个例子说明，记忆的价值不仅在于重复一个值，还在于在后续任务中正确使用当前信息。MemoBench 面向开发者，把公开对话、私有事件账本、回答、可观察工具动作与文件结果组织到可复跑的评测流程。

当前交付有 v2 协议、合成候选数据、结构化评分、适配与隔离检查、离线 runner 和静态报告。离线 fixture 验证数据流，不代表真实助手能力。目标使用方式是修改记忆实现后重跑固定故事，定位旧值复用、主体混淆、遗忘披露或任务产物缺失。

**【待补：真实用户/开发者反馈及使用场景验证；不得用假想访谈代替】**

## 第3页｜相关工作与差异

依据已归档研究材料：LongMemEval 提供长期记忆问答与更新等评测借鉴；MemBench 提醒兼顾记忆过程与能力覆盖；AMA-Bench 将行动轨迹纳入讨论；StateMemBench 强调状态变化。论文版本、原始协议与许可应在正式引用前核验，本稿不提供未复现的横向数字。

MemoBench 的预期差异在工程组合：固定故事回归、可解释评分、openKylin 接入与真实文件验收。不主张首创状态跟踪、首次评测长期记忆，也不声称全面领先已有基准。外部基准子集必须保留原题与原评分规范，并标注子集，不能混比论文全量数字。

**【待补：最终参考文献的原始链接、版本、访问记录及许可核验】**

## 第4页｜架构与真值边界

数据流：公开观察 → 分会话 observe/end_session → component recall + 固定 Reader，或 native 自身 query → Prediction → 私有 Gold 评分 → 原始结果与静态报告。协议见 [spec-v0.2.md](spec-v0.2.md)。公开输入白名单不含 gold、标准答案、类别与故事 split；观察里的事实本身是正常输入。

同一 episode 的新会话不能 reset 长期记忆；不同 episode 和改写必须隔离。ready、durable、unknown 分开记录；未知用量不能填零。异步写入未就绪不得继续查询并伪装成功。operation_id 用于重试去重。native 答案不能由公共 Reader 代答。

文件验证仅适用于测试目录和白名单动作；cwd 不是安全沙箱。当前 native 外部权限隔离未验收，runner 明确 blocked。不能从 JSON 接口推断 MCP 兼容，也不能从 CLI 单次调用推断长期记忆已开启。

## 第5页｜数据设计与审核

当前 manifest：60 个独立候选故事、每故事2种表达，共120个问答；开发12故事/24问答，测试候选48故事/96问答；正式测试集0。每项官方能力有2开发、8测试候选。12故事提供2K/8K/32K字符配对负载；字符不是 token，改写和负载不是新的独立样本。

事件账本先回放计算真值，再生成文本。事件、措辞、噪声随机源分离；改变噪声不改变核心问题与 gold。故事和情节模板按 dev/test 隔离，但语义近重复仍需人工复核。数据为离线、AI辅助编写的合成材料，无真实用户代表性保证。

全部60个账本与问题待核对；边界、冲突、遗忘逐条审阅，其他至少25%；当前正式门禁要求入选故事的表达都签收。文件动作数据的存在不证明任务执行成功。许可证为 `pending_maintainer_signoff`，不能自动套用代码许可。

**【待补：真实审阅者、时间、逐项签收、拒收原因和维护者数据许可决定】**

## 第6页｜评分与裁判校准

v1 会把“不是 UKUI”中的关键词当正确，也可能接受“不知道，但你住北京”，多字段交换仍因词都出现而通过。v2 使用有键 typed slots，分别记录 answer/unknown/forgotten/conflict；路径和版本不统一小写。否定旧值或合法历史查询不自动判错误复用；删除政策禁止明文披露时，否定句也可能违规。

回答正确、当前值误用、遗忘后披露、未知乱答、证据支持、任务完成各有分母。规则无法判定的自然语言进入语义裁判/人工复核，解析失败不是业务答错。候选回答是不可信内容，不能接受其评分指令，裁判不按系统名称改变标准。

校准计划为20份开发输出调规则，另60份独立留出输出人工盲标，报告一致率、Cohen kappa、混淆矩阵与错误放行率。90%与0.7是项目门槛，不是已达事实；未达标用小集合人工裁决，不发布纯 judge 排名。

**【待补：人工盲标、模型裁判输出、校准报告和实际通过状态】**

## 第7页｜实验结果：三区分开

### Controlled / v1 legacy（已归档诊断）

2026-10-14，seed=42，每类20条，6会话，每会话目标8条用户消息，distract=6；120用例、6策略、720条记录。来源：[汇总](experiments/distract-6/summary.json)、[原始输出](experiments/distract-6/results.jsonl)、[复现记录](experiments/distract-6/README.md)。

| 策略 | 原评分总准确率 | 原泄露率 | 平均上下文字符 |
|---|---:|---:|---:|
| full_context | 100.00% | 0.00% | 865.59 |
| hybrid | 100.00% | 0.00% | 34.26 |
| session_summary | 100.00% | 0.00% | 121.30 |
| profile_store | 83.33% | 0.00% | 70.73 |
| bm25_rag | 75.00% | 15.83% | 78.54 |
| sliding_window | 37.50% | 0.00% | 217.47 |

原分布“始终拒答”基线 **33.33%**（forget 与 abstain 占两类；审计见 FULL_RESPONSE B1）。因此37.50%不能脱离平凡基线解读。满分仅是模板/规则耦合诊断，旧评分有误判，不是可靠自然语言能力或真实产品结果。平均字符不含完整提示和写入成本，不能称为总效率提升；v1 full_context 仅保留 user 消息。旧难度扫描不是严格同故事配对因果实验。

### Component / v2 与 Native Agent / v2

本轮离线实际运行12故事、24个case，执行完成且无失败case，但24条评分均待复核；`publish_ranking=false`。这只验证记录链路。报告指出文件动作合同、遗忘政策、审核状态跨卡不一致，尚未验收文件任务，见 [原始摘要](submission/evidence/offline/summary.json)。

**【待补：固定公共 LLM Reader 的 component 实测结果；当前 echo-fixture 不入榜】**

**【待补：两款真实智能体的 native 结果；当前 blocked】**

正式结果必须包含模型请求/返回名、版本、配置、n_story/n_query/n_repeat、微/宏平均及各能力分母、失败/超时率、逐阶段可观察用量、故事聚类配对 bootstrap 95%区间。online/replay 分开，缓存重放不算独立重复。所有安排任务保留在完成率分母，不能删除超时后报更高准确率。

## 第9页｜开源治理与后续

CI 仅离线、无 secret、托管 runner。**【待补：实际远端 CI run URL、提交及完整日志】**。deb 是可选候选分发，不是已适配标记。**【待补：openKylin 安装、运行、卸载日志】**。
