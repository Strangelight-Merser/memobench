## 修复内容

1. **画像请求缺少边界。** 对真实 DeepSeek 服务的画像预检和 JSON 提取显式使用同模型的非推理模式，提取最多 4096 tokens、累计时限 60 秒，单次 I/O timeout 15 秒；保活空行不能无限延长累计等待，静默读取最多额外等待一个 I/O 超时。预检保持一 token，截断 JSON 报失败。桥接仍保留整进程 300 秒期限，未继续放宽预算。原来的提取 schema、证据校验与加密存储完全保留。
2. **完成评审忽略用户输出格式。** 第 004 轮跨会话检索正确，却额外附带来源说明，旧评审将其判为完成。修复后由原生评审要求执行智能体修正输出；真实对照测试已验证“多余说明 → continue，仅代号 → completed”。桥接原样读取最终回答，原精确匹配标准不变。
3. **智能体误解画像保存时机。** 第 005 轮为保存昵称查找旧版 USER.md，12 步预算耗尽后，原生退出提取器却成功保存昵称。修复只在画像运行时启用时说明自动提取时机和检索工具职责，避免查找或改写内部存储文件；不宣称尚未发生的持久化成功。

DeepSeek 的默认推理模式与参数说明见 [官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。修复前的两次有界对照都成功提取三个字段：默认推理 8.72 秒、非推理 2.56 秒。这并不能唯一确定历史 300 秒等待时服务端在执行什么；已确认的缺陷是原请求缺少边界和一 token 预检与默认推理的冲突。006 的实际调用栈进一步定位到 HTTP 响应体读取；[官方保活说明](https://api-docs.deepseek.com/quick_start/rate_limit/)解释了为何空行会持续刷新普通读取超时。最终补丁用真实 SDK + 模拟保活响应验证累计截止及响应关闭，不把该模拟当作产品实跑成绩。

## 验收口径

原五项：同会话精确回答、独立新会话精确回答、真实文件字节哈希、独立 case 不泄露代号、资源清理。

画像专项四项：每轮原生画像收尾成功、昵称经原生提取写入加密画像、昵称出现在新会话实际原生 system_prompt、独立新会话精确回答昵称。检查使用上游只读 `load_profile` 和 state.db；不向产品填充画像或答案，不导出加密密钥。

实跑入口（在仓库根目录，输出目录必须不存在）：

```sh
python3 tools/probe_native_vm.py --ssh-config ../.local-vm/ssh_config --product kylin --out /tmp/memobench-kylin-new --live
```

该命令调用已配置的真实模型并产生用量。模型 `deepseek-flash`；主智能体工具预算 12 步、画像提取最多尝试两次（SDK 内部重试关闭）。当前使用本地修复版本，不能冒称上游默认版本成绩。
